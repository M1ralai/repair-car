# 4.2. Admin Dashboard (Genel Bakış)

## Sayfanın Amacı
Sistemin genel sağlığını, özet istatistiklerini ve o an gelişmekte olan son aktiviteleri (Feed) tek bir merkezi arayüzde admin'e sunmak.

## Sayfa Layout (Yerleşimi)
* **Admin Layout (Dashboard Layout):**
  * Sol tarafta, tüm yönetim modüllerine geçişi sağlayan kalıcı Ana Navigasyon (Sidebar).
  * Üstte, kullanıcı profili ayarları ve sistem bildirimlerinin olduğu Topbar/Header.
  * Ortada ve geri kalan genişlıkta verilerin yer alacağı Scroll barındıran asıl içerik alanı.

## Sözel Olarak Component (Bileşen) İhtiyaçları
* **Sidebar / Navigation Component:** Diğer admin sayfaları arasında (Servis Başvuruları, Talepler vb.) hızlı gezinmeyi sağlayan, aktif sayfayı vurgulayan menü bileşeni.
* **Statistic Card Component:** Üst kısımda grid şeklinde dizilmiş özet verileri gösteren kartlar (Örn: Toplam Kullanıcı Sayısı, Toplam Onaylı Servis Sayısı, Anlık Aktif Talepler, Tamamlanan İşlemler ve Çözülmeyi Bekleyen Şikayetler).
* **Activity Feed (Timeline) Component:** Sisteme dahil olan son taleplerin, platform olaylarının veya yeni alınan başvuruların kronolojik akış halinde listelendiği besleme alanı (Feed).
* **Chart Component (Opsiyonel ama Önerilen):** Platformdaki taleplerin veya servis başarımlarının zamana (gün/hafta) yayılan görsel grafikleri.

## Sözel Olarak Veri Tipleri (Types/Interfaces)
* **`DashboardSettings`** veya **`DashboardStats`**:
  * `totalUsers` (number)
  * `totalApprovedServices` (number)
  * `activeRequests` (number)
  * `completedJobs` (number)
  * `pendingComplaints` (number)
* **`ActivityFeedItem`**:
  * `id` (string)
  * `type` (enum: 'new_service_request', 'new_complaint', 'job_completed', 'alert')
  * `description` (string)
  * `timestamp` (string / Date)
  * `relatedEntityId` (string)

## Davranışlar ve Akış
1. Admin giriş yapıp yetkilendirildikten sonra uygulamanın varsayılan yönetim ekranı olarak bu sayfa yüklenir.
2. Sayfa render olduğunda, sayfanın ihtiyacı olan `DashboardStats` ve `ActivityFeedItem` listesi `infrastructure/mockData` üzerinden çekilir.
3. Dumb UI componentlerine (kartlar, liste) statik veriler ilgili interface prop'ları üzerinden aktarılarak ekrana basılır.
4. Yönetici Aktivite Listesi içerisinden bir olaya (Örneğin: "Servis başvuru talebi geldi") tıkladığında, ilgili işlemin detayının yönetildiği ana modüle (Örn: Sayfa 4.3'teki Onay sürecine) doğrudan yönlendirilir.
