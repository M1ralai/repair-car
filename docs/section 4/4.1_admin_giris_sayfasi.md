# 4.1. Admin Giriş Sayfası

## Sayfanın Amacı
Admin (sistem yöneticisi) yetkisine sahip kullanıcıların yönetim paneline (Web Paneli) güvenli bir şekilde yetkilendirilerek giriş yapabilmesini sağlamak.

## Sayfa Layout (Yerleşimi)
* **Auth Layout:** Sistem genelindeki sidebar veya karmaşık header (üst menü) yapıları bu ekranda bulunmaz.
* **Tasarım:** Sayfa genellikle tam ekran, ortalanmış bir login kartı barındırır. Sürdürülebilir Clean Architecture yapısına uygun, "Sky & Slate" konseptli temiz bir Login iskeleti olmalıdır.

## Sözel Olarak Component (Bileşen) İhtiyaçları
* **Logo / Banner Component:** RepairCar logosu ve "Yönetici Paneli" ibaresi yer almalıdır.
* **Text Input Component (Email / Username):** Yöneticinin kullanıcı adını veya e-postasını girmesi için giriş alanı.
* **Password Input Component:** Şifre giriş alanı (Gizle/Göster aksiyonuna eksiksiz sahip).
* **Button Component:** "Giriş Yap" fonksiyonunu yürütecek, tıklanınca loading (yükleniyor) durumuna geçebilecek ana aksiyon butonu.
* **Alert / Notification Component:** Hatalı giriş yapıldığında belirecek sistem uyarı kutucuğu (Örn: Toast ya da Card içi uyarı mesajı).

## Sözel Olarak Veri Tipleri (Types/Interfaces)
* **`AdminLoginCredentials`**:
  * `email` (string)
  * `password` (string)
* **`AuthResponse`**:
  * `token` (string)
  * `adminDetails` (object)

## Davranışlar ve Akış
1. Admin yetkilisi sayfaya gelir.
2. Email ve şifre bilgilerini doldurur.
3. Form, Presentation katmanında (Dumb Component seviyesinde) kendi validasyonunu yapar (Örn: Alanlar dolu mu?, Email formatı geçerli mi?).
4. "Giriş Yap" butonuna tıklanır.
5. Infrastructure katmanındaki **Mock Data** sağlayıcısına kimlik doğrulama isteği simüle edilir.
6. Dönüş başarılıysa, Authorization token'ı state/storage tarafında saklanır ve yönlendirme (Routing) ile `4.2 Admin Dashboard (Genel Bakış)` sayfasına gidilir.
7. Dönüş başarısızsa Alert component'i ekranda "Geçersiz e-posta veya şifre" uyarılarını gösterir.
